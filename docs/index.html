The point

It saves real files, where they really live

Exporting to a downloads folder and dragging files back where they belong is the worst part of every browser tool, so Myrling doesn't do that. Open PNGs — or drop them on the window — and Save over writes your edits straight back into the originals, wherever they live. The path bar shows the file's true folder, not a guess.

Starting from a blank sprite instead? Press Change…, pick any folder once, and Save writes every frame there — name‑0.png, name‑1.png — straight into your game's art directory. Works in Chrome and Edge through the File System Access API, and in the Mac app natively.

Guardrails

Your game's rules ride along while you draw

Myrling was born inside Realms of Eldermyr, whose art packer refuses files that break its rules. So the editor checks them live, the same way the packer does, and is honest about which problems block you and which are just worth a look:

Refused. Part see-through pixels, a non-square picture, more than 32 colours, an empty frame, a name that cannot be a filename.

Worth a look. Nothing on the bottom row — the game plants that row at the creature's feet, so it would hover. One frame only. No clear pixels at all.

Clean. What you drew is what ships, pixel for pixel. No outline added, no shadow to paint; the game does both.

Not shipping into Eldermyr? One checkbox turns the rules off: soft, part see-through pixels and any colour count are then kept exactly as painted, through save, export and browser storage alike. And the rules themselves are ordinary code in one readable file — fork it and make it enforce your game's rules instead.

The editor

Small tool, sharp edges

An honest brush D

Pencil, fill, eraser, and a line tool that snaps every drag to flat, upright, or a true one-for-one diagonal. An opacity slider blends paint with what's underneath — once per stroke, so a slow drag never darkens its own line.

Frames that behave

Add, copy, delete, drag tiles to rearrange. Onion skin shows the frame before, faintly. Play runs the walk cycle at game size, which is the only honest way to judge one.

Copy, paste, between sprites ⌘C ⌘V

Select a box, copy it, paste it into the same sprite or a different one. Pastes land floating so you drag them into place before they set down.

Judged at game size

A 16-pixel sprite tells you nothing at 16 pixels. The preview draws yours the size a player sees it, on the game's grounds, next to a grave rat, the hero and an ogre already in the game.

Keys, yours to change ⌘,

Every tool key rebinds in Settings — click a key, press a new one. A taken key swaps so nothing goes unreachable. Kept in your browser.

Zoom that follows you

The wheel zooms around your cursor: the pixel under it stays under it. The side columns drag wider when the sprite list or panels need room.

The Mac app

The same file, in its own window

Not a port — the Mac app is index.html, unchanged, behind a single Swift file. WebKit has no File System Access API, so a 100-line bridge fills in the corner Myrling uses: real open panels, real folder pickers, Save over writing real files, exports landing in Downloads. Build it with the Xcode command line tools and nothing else:

git clone https://github.com/Josiah-Turnquist/myrling-sprite-editor
cd myrling-sprite-editor
make run    # builds dist/Myrling.app and opens it

Built for your machine, ad-hoc signed — all a local tool needs. The Dock icon is itself a 16-pixel sprite, drawn by a hundred lines of dependency-free Python.

Take it

MIT, for whatever you're making

The whole tool is readable in an afternoon: one HTML file for the editor, one Swift file for the shell, one script for the icon. Swap the palette, the checks and the reference creatures for your own game's, and you have a sprite editor that knows your rules.
